# 开发文档 03 · 操作手册（复现 / 加模块 / 运维 / 排障）

> 2026-08-16 重建版。

## A. 从零复现（换机器/重装）

### A1. 环境

```bash
git clone <仓库> wechat-claw && cd wechat-claw
/usr/bin/python3.14 -m venv .venv
.venv/bin/pip install -r requirements.txt      # SDK + acp + lunar-python（版本锁死）
.venv/bin/python patches/apply_patches.py      # 重打 SDK 三处补丁（幂等，报告"已打/跳过/失败"）
```

### A2. systemd 服务

```ini
# ~/.config/systemd/user/wechat-bridge.service
[Unit]
Description=WeChat to opencode bridge (iLink direct)
After=network-online.target
StartLimitIntervalSec=600
StartLimitBurst=3

[Service]
Type=simple
ExecStart=/home/<user>/wechat-claw/.venv/bin/python -m bridge.main
WorkingDirectory=/home/<user>/wechat-claw
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
```

```bash
systemctl --user daemon-reload && systemctl --user enable --now wechat-bridge
```

### A3. 扫码登录

```bash
# 登录失效时（S1：服务会 3 次重启后 failed）
.venv/bin/python -m wechat_agent_sdk ... # 或按 SDK 登录流程运行扫码脚本
systemctl --user restart wechat-bridge
```

### A4. 注册/重置模块

```bash
cd modules && .venv/bin/python register.py <name> [--purpose ...] [--schedule-json '...'] [--retry-json '...']
```

### A5. 验证清单

- [ ] `systemctl --user status wechat-bridge` = active (running)
- [ ] journald：`[weixin] 已连接 iLink` + `[acp] Connection initialized` + `[push] HTTP 入口`
- [ ] 调度活体：`agent-SDK/scheduler_state.json` 的 `todo.last_ts` 每分钟推进
- [ ] push 冒烟：错误 token → 401；`modules/todo/token` 作 Bearer + 合法 body → 200
- [ ] 模块 dry-run：各模块 `--dry-run` 打印素材、rc=0、不写状态文件
- [ ] 媒体接收：微信发一张图片 → journald 无 `[media] 接收失败`、`inbox/` 出现新文件（补丁③/④ 完整性实测）

## B. 加一个新模块（step-by-step）

1. 复制标准骨架：`mkdir modules/<name>`，参照 `开发文档-04-模块开发规范.md` 写 `<name>_worker.py`
2. 写 `module.json`（自声明 schedule/retry/args——见 04 文档格式）
3. 写 `规范.md`（业务行为；调度时间以 module.json 为单一事实源，不重复声明）
4. 注册：`register.py <name> --purpose ... --schedule-json '[...]' --retry-json '...'`
5. 自带 `--dry-run` 验证：`python <name>_worker.py --dry-run` → rc=0
6. bridge 自动发现（build_index 实时扫描），**零改动、无需重启**（新模块下个 tick 即生效）

## C. 常用操作

| 操作 | 命令 |
|---|---|
| 重启 bridge | `systemctl --user restart wechat-bridge` |
| 手动触发（dry） | `cd modules/todo && ../..//.venv/bin/python todo_worker.py --dry-run` |
| 手动触发（真跑） | 同上去掉 `--dry-run` |
| 外部一次性推送 | `curl -X POST 127.0.0.1:9898/push -H "Authorization: Bearer <push_token>" -d '{"type":"briefing","text":"..."}'` |
| 微信要文件（agent 发原件） | 微信说"发我 <路径>" → agent `bash` curl 调 `/push`（type=file，`"path":"..."`） | 见"发送范围三级规则" |
| 查统一日志 | `tail -f logs/system.log`（JSON Lines，按 module/event 过滤） |
| SDK 升级 | 装新版本 → `patches/apply_patches.py` 重打（报告异常则停止排查版本差异） |

### 发送范围三级规则（_send_file 单点执行）

| 级别 | 范围 | 行为 |
|---|---|---|
| default 直发 | `~/文档` `~/下载` `~/桌面` `~/图片` `~/音乐` `~/视频` `~/公共` `~/wechat-claw/inbox`（含子目录） | 免确认直接发送 |
| gate 确认 | 其余任何路径 | 微信收到「请求发送文件：<绝对路径>」，回复允许/拒绝，30s 无回复默认拒绝 |
| reject 拒绝 | token/密钥类：文件名含 token/secret/credential/private、`anniversaries.json.enc`、扩展名 `.key/.pem/.p12/.pfx/.p8`、`~/.ssh/**`、`~/.gnupg/**`、`~/.config/wechat-claw/**` | 直接拒绝，任何通道、任何确认都不放行；微信收到拒绝回执 |

路径先经 `resolve()` 规范化（`../`、符号链接均解析后再分级，越界按目标重判）。模块通道（planner 时政原件在 `~/公共`）走 default 直发，不受影响。

## D. 排障

| 症状 | 检查 | 处置 |
|---|---|---|
| 微信无响应但服务 active | `systemctl --user status` 是否 failed（S1 循环被限）→ journald 找 `SessionExpiredError`/`未登录` | 重新扫码登录 |
| 早报没到 | `modules/planner/morning_sent.json` 有无当天键；`scheduler_state.json` planner 有无 `morning_failed` | 有 failed：看统一日志确认重试链；无键无 failed：查 scheduler tick |
| 时政文件没收到 | 统一日志 `file_push_fail` | 早报会补一句说明；检查 `~/公共/时政简报/` |
| /push 401 | journald `鉴权失败` 行（IP + token 前 4 位） | 模块 token 被重置？重跑 register |
| 消息重复推送 | 防重文件（*_sent.json）是否可写 | 权限/磁盘检查；`logs/system.log` 找 io 写失败 |
| 媒体"微信端下载失败" | SDK 补丁是否在位 | `patches/apply_patches.py --check-only` |
