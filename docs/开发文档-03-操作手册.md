# 开发文档 03 · 操作手册（复现 / 加模块 / 运维 / 排障）

> 2026-08-16 重建版。
>
> **占位符约定**：`<PROJECT_ROOT>` = 项目部署目录（clone 所得）。例：
> Linux/macOS `/home/<user>/wechat-claw`；Windows `C:\Users\<user>\wechat-claw`。
> 各平台专属命令已标注 [Linux] / [macOS] / [Windows]。

## A. 从零复现（换机器/重装）

### A1. 环境

```bash
git clone <仓库> wechat-claw && cd wechat-claw     # 下文以 <PROJECT_ROOT> 代指此目录
python3 -m venv .venv                               # 需 Python >= 3.11
.venv/bin/pip install -r requirements.txt           # SDK 依赖 + acp + lunar-python（版本锁死）
.venv/bin/pip install -e ./vendor/wechat_agent_sdk  # SDK 0.2.1 快照（4 处补丁已预打）
.venv/bin/python patches/apply_patches.py --vendor --check-only   # 校验：期望 4 处 [SKIP] 已打
```

[Windows] 环境：`python -m venv .venv`（python 为 3.11+ 解释器），后续命令路径换成
`.venv\Scripts\python.exe` / `.venv\Scripts\pip.exe`。

> 生产库（非本仓库）路径：`pip install wechat-agent-sdk==0.2.1` 后
> `patches/apply_patches.py`（无参数）重打补丁；本仓库为 vendor 快照预打，`--vendor --check-only` 只校验。

### A2. 守护进程（按平台）

#### A2a. [Linux] systemd 服务

```ini
# ~/.config/systemd/user/wechat-bridge.service
[Unit]
Description=WeChat to opencode bridge (iLink direct)
After=network-online.target
StartLimitIntervalSec=600
StartLimitBurst=3

[Service]
Type=simple
ExecStart=<PROJECT_ROOT>/.venv/bin/python -m bridge.main
WorkingDirectory=<PROJECT_ROOT>
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
```

```bash
systemctl --user daemon-reload && systemctl --user enable --now wechat-bridge
```

#### A2b. [macOS] launchd 服务

```xml
<!-- ~/Library/LaunchAgents/wechat-bridge.plist -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>wechat-bridge</string>
    <key>ProgramArguments</key>
    <array>
        <string><PROJECT_ROOT>/.venv/bin/python</string>
        <string>-m</string>
        <string>bridge.main</string>
    </array>
    <key>WorkingDirectory</key>
    <string><PROJECT_ROOT></string>
    <key>KeepAlive</key>
    <true/>
    <key>ThrottleInterval</key>
    <integer>600</integer>
    <key>RunAtLoad</key>
    <true/>
    <key>StandardOutPath</key>
    <string>/tmp/wechat-bridge.out.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/wechat-bridge.err.log</string>
</dict>
</plist>
```

```bash
launchctl load -w ~/Library/LaunchAgents/wechat-bridge.plist
```

语义对应：`KeepAlive` = 崩溃自动拉起（systemd Restart=on-failure）；
`ThrottleInterval`(600) = 崩溃重启节流（systemd StartLimitInterval/Burst）。

#### A2c. [Windows] nssm 服务化

```powershell
# nssm 已随仓库 vendor（vendor/nssm/，public domain），无需另行安装；
# 按系统架构选 win64.exe / win32.exe，路径以实际为准（以下示例用 win64）
$nssm = "<PROJECT_ROOT>\vendor\nssm\win64.exe"
& $nssm install wechat-bridge "<PROJECT_ROOT>\.venv\Scripts\python.exe" -m bridge.main
& $nssm set wechat-bridge AppDirectory "<PROJECT_ROOT>"
& $nssm set wechat-bridge AppExit Default Restart   # 崩溃自动重启（对应 Restart=on-failure）
& $nssm set wechat-bridge AppRestartDelay 10000      # 重启间隔 10s（对应 RestartSec）
& $nssm start wechat-bridge
```

### A3. 登录（扫码）

- **主路径（web 初始化向导）**：web 初始化向导提供扫码登录界面（SDK 程序化登录
  `request_login`/`check_login`，token 写入 SDK storage，bridge 启动自动复用）。
  web 上线前或无 web 场景，使用下方过渡脚本。
- **过渡脚本（web 上线前）**：在项目根执行一次（token 保存后长期有效，失效时重跑）：

```bash
.venv/bin/python - <<'EOF'
import asyncio
from wechat_agent_sdk.transport import WeChatTransport
asyncio.run(WeChatTransport(account_id="default").login_terminal())
EOF
```

- 登录失效时（S1：服务会 3 次重启后 failed）：重新执行上述登录流程，然后重启服务
  （[Linux] `systemctl --user restart wechat-bridge` /
  [macOS] `launchctl kickstart -k gui/$UID/wechat-bridge` / [Windows] `nssm restart wechat-bridge`）

### A4. 模块管理（register.py 唯一入口）

```bash
cd modules && .venv/bin/python register.py <name> [--purpose ...] [--schedule-json '...'] [--retry-json '...']  # 注册（新模块默认关闭）
.venv/bin/python register.py --enable <name>     # 启用（开始调度/推送放行）
.venv/bin/python register.py --disable <name>    # 关闭（不调度、推送不放行）
.venv/bin/python register.py --list              # 列表（含启停状态）
.venv/bin/python register.py --uninstall <name>  # 卸载（删除模块文件，不可恢复）
```

### A5. 验证清单

- [ ] `systemctl --user status wechat-bridge` = active (running)
- [ ] [Linux] journald：`[weixin] 已连接 iLink` + `[acp] Connection initialized` + `[push] HTTP 入口`
- [ ] 调度活体：`agent-SDK/scheduler_state.json` 的已装模块 `<name>.last_ts` 每分钟推进
- [ ] push 冒烟：错误 token → 401；已装模块 `modules/<name>/token` 作 Bearer + 合法 body → 200
- [ ] 模块 dry-run：各模块 `--dry-run` 打印素材、rc=0、不写状态文件
- [ ] 媒体接收：微信发一张图片 → journald 无 `[media] 接收失败`、`inbox/` 出现新文件（补丁③/④ 完整性实测）

## B. 加一个新模块（step-by-step）

> 模块在**模块源工作区**（项目根 `wechat-claw_modules_official/<name>/`）开发，发布到独立仓库
> `wechat-claw_modules_official`；部署时拷贝到主项目 `modules/<name>/`（安装见模块源 README）。
> 主项目 `modules/` 只放平台（common + register/registry_index），不内置业务模块。

1. 复制标准骨架：`mkdir wechat-claw_modules_official/<name>`，参照 `开发文档-04-模块开发规范.md` 写 `<name>_worker.py`
2. 写 `module.json`（自声明 schedule/retry/args/settings_schema——见 04 文档格式）
3. 写 `规范.md`（业务行为；调度时间以 module.json 为单一事实源，不重复声明）+ `agents.md`（agent 维护指引）
4. 注册：`register.py <name> --purpose ... --schedule-json '[...]' --retry-json '...'`，再 `register.py --enable <name>` 启用
5. 自带 `--dry-run` 验证：`python <name>_worker.py --dry-run` → rc=0
6. bridge 自动发现（build_index 实时扫描），**零改动、无需重启**（新模块下个 tick 即生效）

## B2. 卸载 / 删除模块

- **CLI**：`register.py --uninstall <name>` 默认**保留用户数据**（`modules_data/<name>/`，重装可沿用）；加 `--purge-data` 连数据一起删（不可恢复）
- **web**：模块管理 → 删除 → **二次确认弹窗** + 小圆圈选项（勾 = 连用户数据一起删；不勾 = 保留数据，默认不勾）

## B3. 备份

- **备份 = `modules/modules_data/` + `.config/`** 两个目录打包，即完整用户数据 + 配置
- 恢复：解包回原位即可（模块代码可从模块源重新安装）

## C. 常用操作

| 操作 | 命令 |
|---|---|
| 重启 bridge [Linux] | `systemctl --user restart wechat-bridge` |
| 重启 bridge [macOS] | `launchctl kickstart -k gui/$UID/wechat-bridge` |
| 重启 bridge [Windows] | `nssm restart wechat-bridge` |
| 手动触发（dry） | `cd modules/<name> && ../../.venv/bin/python <name>_worker.py --dry-run` |
| 手动触发（真跑） | 同上去掉 `--dry-run` |
| 外部一次性推送 | `curl -X POST 127.0.0.1:9898/push -H "Authorization: Bearer <push_token>" -d '{"type":"briefing","text":"..."}'` |
| 微信要文件（agent 发原件） | 微信说"发我 <路径>" → agent `bash` curl 调 `/push`（type=file，`"path":"..."`） | 见"发送范围三级规则" |
| 查统一日志 | `tail -f logs/system.log`（JSON Lines，按 module/event 过滤） |
| SDK 升级 | 装新版本 → `patches/apply_patches.py` 重打（报告异常则停止排查版本差异） |

### 发送范围三级规则（_send_file 单点执行）

| 级别 | 范围 | 行为 |
|---|---|---|
| default 直发 | `~/文档` `~/下载` `~/桌面` `~/图片` `~/音乐` `~/视频` `~/公共` `~/wechat-claw/inbox`（含子目录） | 免确认直接发送 |
| gate 确认 | 其余任何路径 | 微信收到「请求发送文件：<绝对路径>」，回复允许/拒绝，30s 无回复默认拒绝 |
| reject 拒绝 | token/密钥类：文件名含 token/secret/credential/private、`anniversaries.json.enc`、扩展名 `.key/.pem/.p12/.pfx/.p8`、`~/.ssh/**`、`~/.gnupg/**`、项目根 `.config/**` | 直接拒绝，任何通道、任何确认都不放行；微信收到拒绝回执 |

路径先经 `resolve()` 规范化（`../`、符号链接均解析后再分级，越界按目标重判）。模块发送数据区内的文件（如简报原文 `modules_data/<name>/briefing/`）走模块通道，不占微信确认。

## D. 排障

| 症状 | 检查 | 处置 |
|---|---|---|
| 微信无响应但服务 active | [Linux] `systemctl --user status` 是否 failed（S1 循环被限）→ journald 找 `SessionExpiredError`/`未登录`；[macOS] `launchctl list \| grep wechat-bridge` / `log show --last 1h --predicate 'process == "python"'`；[Windows] `nssm status wechat-bridge` / 事件查看器 | 重新扫码登录 |
| 早晚报没到 | 数据区 `modules_data/<name>/morning_sent.json`（或 evening）有无当天键；`scheduler_state.json` 对应模块有无 `morning_failed` | 有 failed：看统一日志确认重试链；无键无 failed：查 scheduler tick |
| 简报文件没收到 | 统一日志 `file_push_fail` | 推送会补一句说明；检查 `modules_data/<name>/briefing/` |
| /push 401 | [Linux] journald `鉴权失败` 行（IP + token 前 4 位）；其他平台看服务日志 `logs/system.log` 同键 | 模块 token 被重置？重跑 register |
| 消息重复推送 | 防重文件（*_sent.json）是否可写 | 权限/磁盘检查；`logs/system.log` 找 io 写失败 |
| 媒体"微信端下载失败" | SDK 补丁是否在位 | `patches/apply_patches.py --vendor --check-only` |
