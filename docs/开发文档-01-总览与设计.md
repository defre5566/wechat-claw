# 开发文档 01 · 总览与设计（wechat-claw 微信主动推送体系）

> 2026-08-16 重建版：venv 项目化 + common 母模组 + bridge 通用引擎 + registry 自描述。
> 本文档基于实物（代码）编写，旧版根目录文档已收编至此目录。

## 架构总览

```
微信 ← iLink Bot API ← wechat-agent-sdk transport ← opencode ACP 子进程
                              ↑                          ↑
                    推送入口 /push（9898）        消息处理 / 权限确认
                              ↑
               ┌──────────────┴───────────────┐
               │ bridge/（基础设施，零业务知识）│
               │  main · push_server · scheduler · session │
               └──────────────┬───────────────┘
                              │ build_index() 读
               ┌──────────────┴───────────────┐
               │ modules/（业务模块，自描述）  │
               │  todo / planner / emotion + module.json │
               │  common/（数据公共库）        │
               └──────────────────────────────┘
```

**分层原则**：
- **bridge** = 基础设施：调度引擎、推送入口、会话、权限。**不承载任何模块业务知识**（不认识"早报""窗口"），全部规则来自各模块的 `module.json`
- **modules** = 业务：worker 逻辑 + 自描述配置（调度/重试策略自声明）
- **common** = 数据公共库：共享函数/数据结构/常量/缓存/日志/加解密，模块经它读写数据

## 配置化（基础设施层）

- 配置入口：`modules/common/config.py`，读 `~/.config/wechat-claw/config.yaml`（不放置 = 全部内置默认，老用户零影响；部分配置深合并生效）
- 可配项：推送入口（host/port/body 上限/重试）、会话窗与权限确认超时、调度超时与状态修剪天数、日志轮转、ACP 命令/端口、文件发送三级清单、密钥路径
- 三模块业务配置（城市/位置/vault 路径/时政目录）**不在本层**，属后续模块配置化范围
- 运行期启动时读取一次，改配置需重启生效

## 调度机制（通用引擎）

- 各模块 `module.json` 声明 `schedule`（三态）+ `retry`：
  - `{"every": "1m"}`：间隔触发（todo）
  - `{"id": "morning", "cron": "29 8 * * *", "args": ["--phase","morning"]}`：cron 触发（planner）
  - `{"window": {"hours": "8-21", "offset": "random-5-50"}}`：小时窗口 + 随机偏移（emotion，严格版：窗口首 tick 定偏移并缓存）
- scheduler 每分钟 tick：遍历 index → 判定触发 → spawn 模块（300s 超时保护）→ 读退出码：
  - rc=0 → 记成功（cron 规则记 `id=today`；every 记 `last_ts`；window 记 `hour_key`）
  - rc≠0 → 记 `{id}_failed={ts,count}`，按 retry 配置补发（间隔内重试，≤max 次；planner 900s×3）
- **补发语义**：模块失败 rc=1 → 当天补发；3 次后放弃，次日按 cron 自然重来

## 模块准入（token 验算）

- 注册：`python3 modules/register.py <name>` → 生成 token（0600，明文只在模块目录）+ 更新 `module.json`
- 验算：bridge 对请求 token 算 sha256，命中 index 任一模块哈希 → 放行；401 记日志（IP + token 前 4 位）
- index 由 `registry_index.py` 实时扫描 module.json + token 文件计算——**token 轮换自动生效，无过期注册表**

## 权限体系

| 操作 | 策略 |
|---|---|
| 读 | `read ~/** allow`；**deny：`modules/**/token`、`agent-SDK/push_token`、`anniversaries.json.enc`、`~/.config/wechat-claw/secret.key`** |
| 写类（edit/write/bash） | 默认 ask → 微信确认（30s 无回复默认拒绝） |
| 豁免 | `~/文档/private/01-Todo/**` edit\|write |

## 安全要点

- token 文件 agent 不可读（deny）→ 防伪造 /push（任意文件外发链已断）
- 文件发送三级规则（bridge/paths.py，_send_file 单点执行）：个人目录（`~/文档/下载/桌面/图片/音乐/视频/公共`、`~/wechat-claw/inbox`）直发；其余路径走微信确认（明示绝对路径，30s 超时拒绝）；token/密钥类（文件名模式 + `~/.ssh`、`~/.gnupg`、`~/.config/wechat-claw`）任何情况直接拒绝。路径经 resolve 规范化防 `../` 与符号链接绕过
- 隐私数据（纪念日/生日）AES-GCM 加密存储（common/crypto.py），密钥 chmod 600 + deny
- /push body 上限 100MB（413）；队列有界（100，满则 503）
- S1：SessionExpiredError → critical 日志 + 非零退出 → systemd StartLimit 终止循环（3 次后 failed 状态）
- 统一日志：模块事件走 common.log_event（JSON Lines）；bridge 用标准 logging 写同一文件（1MB 轮转 ×2），stderr 副本进 journald
