# 开发文档 04 · 模块开发规范（标准骨架 / 流程 / 铁律）

> 2026-08-16 重建版。新增模块一律照此开发，保证与 bridge 通用引擎无缝协作。

## 1. 标准目录结构

```
modules/<name>/
├── <name>_worker.py   ← 标准骨架（见下）
├── module.json        ← 自描述（真源：调度/重试/入口参数）
├── 规范.md            ← 业务行为自述（调度时间以 module.json 为唯一事实源，不重复声明）
├── token              ← register.py 生成（0600）
└── <name>_sent.json   ← 防重状态（可含其他状态文件）
```

## 2. worker.py 标准骨架

    ...

    argv = argv or sys.argv[1:]

        return 0

## 3. module.json 格式

```json
{
  "name": "<name>",
  "purpose": "一句话用途",
  "spec": "规范.md",
  "schedule": [ <三态之一或组合> ],
  "retry": {"interval_seconds": 900, "max": 3} | null
}
```

**入口参数在 schedule 规则内嵌 `args`（见 cron 形态），不设顶层 args 字段**（死数据）。

**schedule 三态**：
| 形态 | 示例 | 语义 |
|---|---|---|
| every | `{"every": "1m"}` | 间隔触发（m/h/s 后缀） |
| cron | `{"id": "morning", "cron": "29 8 * * *", "args": ["--phase","morning"]}` | 标准 5 段（* 或数字）；`id` 为成功状态键；`args` 传给 worker |
| window | `{"window": {"hours": "8-21", "offset": "random-5-50"}}` | 小时窗口 + 随机偏移（首 tick 定偏移缓存，错过窗口跳过不补） |

**retry 语义**：模块失败（rc≠0）→ scheduler 按 `interval_seconds` 间隔补发，最多 `max` 次；`null` = 失败只记日志不补发。todo 用 `60s×0`（every 本身每分钟重试）。

## 4. 开发流程

1. 建目录 + 写 worker（骨架 + 业务）
2. 写 module.json（调度/重试自声明）
3. 写 规范.md
4. `register.py <name> --purpose ... --schedule-json '...' --retry-json '...'`（token + 0600 + module.json 更新）
5. `python <name>_worker.py --dry-run` 验证（rc=0、不写状态文件）
6. bridge 自动发现（build_index），零改动接入

## 5. 铁律

1. **业务知识只进 worker.py + module.json**；公共能力只调 common；**禁止改 bridge 引擎**（引擎需求 → 配置化表达）
2. **调度时间以 module.json 为唯一事实源**，规范.md 不重复声明（防文档漂移）
3. **跨模块数据交换只走 common.shared_load/shared_save**，禁止互读文件
4. 缓存类共享数据必须带 TTL（防过期数据）
5. 失败必须 return 1（scheduler 才能感知补发）；测试必须用 `--dry-run`（真跑会推微信）
6. 新模块接入后跑 03 文档 A5 验证清单

## 6. common 边界清单（新增共享代码必须属于下列类别）

1. 任务解析（task.py）
2. 防重/状态 IO 与共享数据（io.py + shared/）
3. 外部数据（weather.py 天气/花粉）
4. 时间与历法（calendar.py 农历/节气/三伏、holidays.py 节假日）
5. 推送客户端（push.py）
6. 加解密（crypto.py）
7. 日志（log.py）
8. 位置常量（locations.py）

**阈值**：common 包单文件超 ~400 行，或出现"某功能只被一个模块用"→ 拆分子模块/回迁模块目录。
