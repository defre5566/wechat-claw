# 开发文档 04 · 模块开发规范（标准骨架 / 流程 / 铁律）

> 2026-08-19 更新版（同步 G1-G5 / H1-H8 / cron 增强 / once / 入站路由 / 长任务分工 / opencode scheduler 打包 / **模块化完整定稿**）。
> 2026-08-21 更新：**部署状态迁移**——enabled/retry/auto_update 归数据区 settings.json（module.json 纯声明化）；新增 installed.json 版本记录 + 每日自动更新（指纹驱动，静默）。
> 新增模块一律照此开发，保证与 bridge 通用引擎无缝协作。

## 1. 标准目录结构（代码 / 用户数据分家）

```
modules/<name>/            ← 模块代码（升级可整体替换，不碰用户数据）
├── <name>_worker.py   ← 标准骨架（见下；可选支持 --inbound 入站模式）
├── module.json        ← **纯声明**（真源：调度/入口参数/入站订阅/**settings_schema 声明**/permissions 越界豁免/静态 schedule）
│                          ※ 不再承载部署状态（enabled/retry/auto_update）——更新整体替换零抢救
├── 规范.md            ← 业务行为自述（调度时间以 module.json 为唯一事实源，不重复声明）
├── agents.md          ← agent 维护指引（写/改/查数据）
├── token              ← register.py 生成（0600）；仅缺失时补发（--reissue-token）；删除重装 = 新 token
├── timer.json         ← 【可选】代码型长任务的定时声明（见 §7）
└── job.template.json  ← 【可选】agent 型长任务的 job 模板（见 §7）

modules/modules_data/<name>/   ← ★ 用户数据 + 部署状态（备份对象，升级/更新/重装不覆盖，git 不同步）
├── settings.json      ← **部署状态（enabled/retry/auto_update）+ 业务设置统一落盘**（register 唯一入口）
├── installed.json     ← 版本记录（{version, installed_at, source_id}，安装/更新时写）
└── …                  ← 模块业务数据 + 运行时状态（任务文件、防重记录等）
```

- **备份 = `modules/modules_data/` + `.config/`**（两个目录打包即完整用户数据+配置）
- **模块名即唯一 id**：目录 = 数据目录 = 豁免关联 = 日志关联；**模块名不可变，改名视为新模块**
- 同名模块（不同来源）：安装机制拦截（同名 = 已存在，拒绝/提示）
```

## 2. worker.py 标准骨架

```python

    load_token, post_push, log_event,  # 按需增删（如 shared_load 等）
)

MODULE_DIR = Path(__file__).resolve().parent
SENT_FILE = MODULE_DIR / "<name>_sent.json"

def build_material(...) -> str:   # 业务①：构造素材
    ...

def main(argv: list[str] | None = None) -> int:
    argv = argv or sys.argv[1:]
    dry = "--dry-run" in argv      # 必须支持（测试无副作用）
    # phase = ...                 # 可选：--phase 多阶段（早晚报型模块）
    # inbound 模式（可选，见 §6）：--inbound <text> --conversation <id>
    #   rc=0 + print(回复) = 模块自答；rc=3 = 转 agent；rc=1 = 失败降级 agent

        ...记防重...

    return 1                      # 失败 → scheduler 按 retry 配置补发

    raise SystemExit(main())
```

## 3. module.json 格式

```json
{
  "name": "<name>",
  "purpose": "一句话用途",
  "spec": "规范.md",
  "schedule": [ <四态之一或组合> ],   // 静态声明（如 every 1m）；schedule_from_settings 联动产物也写此
  "schedule_from_settings": [ {"phase": "morning", "time_field": "morning_time", "enabled_field": "report_on"} ],
  "inbound": {"intents": ["暂停关心"], "scope": "all", "priority": 0},
  "settings_schema": [ <模块设置声明，见下> ],
  "permissions": {"edit": ["<越界路径>"], "write": ["<越界路径>"]}   // 【可选】越界豁免申请
}
// ※ 模块包不再写 enabled/retry（部署状态）：安装时 register 写入数据区 settings.json；
//   retry 若在 module.json 声明则安装时复制为默认（此后 web 改的是 settings.json）
```

**settings_schema（模块设置声明，E16 落地）**：模块自己声明设置表单，web 模块参数区**自动渲染**（不针对任何模块写死）；**值存 `modules/modules_data/<name>/settings.json`**（module.json 只留声明，升级不丢），保存走 `register.update_module(settings=...)`（后端校验器 `web/schema/module_schema.py` 清洗/校验）。

**settings 三层归属**：机制（校验器/渲染器）在主体 web（按 schema 通用，零硬编码）；声明（settings_schema）在模块 module.json；值（settings.json）在数据区随用户数据走。

结构（分组数组，数组顺序即页面顺序，section 即小节标题）：
```json
"settings_schema": [
  {"section": "数据源", "desc": "小节标题下的说明文字（可选）",
   "fields": [
     {"key": "data_source", "type": "select",
      "options": [{"value": "internal", "label": "内置数据源"}],
      "default": "internal", "desc": "字段说明（渲染为表单标签）"},
     {"key": "vault_path", "type": "path", "default": "",
      "show_when": {"data_source": "vault"},      // 条件显示：满足才渲染/提交
      "required_when": {"data_source": "vault"}}  // 条件满足时必填（空白拒绝保存）
   ]}
]
```

- 类型集：`string`（文本框）/ `path`（路径框，~ 开头）/ `select`（下拉，options 支持 {value,label} 中文显示名）/ `boolean`（开关）/ `tags`（标签编辑列表）/ `number`（数字框）/ `choice`（多选词条，值 list[str]；候选由调用方注入（如 directions.json 键 + custom prompts 目录），`max` 限最多选数，非法候选静默过滤）
- `show_when`：条件不满足 → 前端隐藏 + 后端丢弃（提交值不落盘）
- `show_when_service`：运行时服务条件（如 pollen/typhoon 按 location 可用性）；声明该字段且服务不可用 → 丢弃提交值（传 None 不校验，向后兼容）
- `required_when`：条件满足但空白 → 前端拦截 + 后端 400
- 页面按钮：`[恢复默认]`（字段回 default）`[保存]` 并列
- 设置属于模块业务配置（铁律：不写 config.yaml）

**enabled**：模块启停开关（register.py 唯一管理入口）。**存数据区 settings.json**（module.json 不再承载部署状态——更新整体替换零抢救）。缺失或 false = 关闭（不调度、推送不放行、不进 index）；显式 true = 启用。**新注册默认 false**，`register.py --enable <name>` 开启。

**retry**：失败补发配置（web 弹窗可配）→ **存 settings.json**；模块包的 retry 字段仅作安装时的默认值声明（安装器复制一次）。

**auto_update**：模块级自动更新开关（弹窗标题栏胶囊）→ **存 settings.json**（默认开跟随全局 update.auto_enabled）。

**入口参数在 schedule 规则内嵌 `args`（见 cron 形态），不设顶层 args 字段**（死数据）。H6：every/window/cron/once 四态统一传规则 args。

**schedule 四态**：
| 形态 | 示例 | 语义 |
|---|---|---|
| every | `{"every": "1m"}` | 间隔触发（m/h/s 后缀） |
| cron | `{"id": "morning", "cron": "29 8 * * *", "args": ["--phase","morning"]}` | 标准 5 段；`id` 为成功状态键；`args` 传给 worker；**支持列表(15,45)/区间(8-21)/步进(*/30)**（cron 增强）；周段 0=周日、`1-5` 表达工作日 |
| window | `{"window": {"hours": "8-21", "offset": "random-5-50"}}` | **每单位时间（小时）窗格内一次随机通知**；首 tick 定偏移缓存；错过窗口跳过不补；失败按 retry 在窗格内补发；**同一模块多条 window 规则 hours 重叠时共享每小时一次**（想多时段固定提醒请用 cron/every） |
| once | `{"once": "2026-09-01T09:00", "args": [...]}` | **一次性提醒**：到点跑一次 → 成功写永久完成勾、永不重跑；失败按 retry 补发、超次不放弃（次日同刻继续直至成功）；"每年纪念日"用 cron 非 once |

**retry 语义**：模块失败（rc≠0）→ scheduler 按 `interval_seconds` 间隔补发，最多 `max` 次；`null` = 失败只记日志不补发。**H5：rc≥2（引擎级异常：脚本缺失/超时/spawn 失败/信号杀）不补发**——every 推进周期、cron/once 自然下次、window 放弃本窗格；rc=1 业务失败照常补发。

**inbound**（可选，入站订阅，见 §6）：`intents` 意图关键词列表（任一命中即路由）；`scope`（`all`/`direct`，本期 `direct` 语义与 `all` 相同，保留字段）；`priority` 多模块竞争优先级（高者先试、接管即止）。

## 4. 开发流程

1. 建目录 + 写 worker（骨架 + 业务）
2. 写 module.json（调度/重试/入站订阅自声明）
3. 写 规范.md
4. `register.py <name> --purpose ... --schedule-json '...' --retry-json '...'`
   - **新模块**：生成 token（0600）+ module.json，**enabled 默认 false**
   - **已存在模块**（G1）：走更新路径，**token 不变、enabled 不变**，只改传入字段
5. `register.py --enable <name>` 开启
6. `python <name>_worker.py --dry-run` 验证（rc=0、不写状态文件）
7. bridge 自动发现（build_index），零改动接入
8. 接入后跑 03 文档 A5 验证清单

**token 管理**：token 只发一次——模块存在期间不换（G1）；仅缺失时 `register.py --reissue-token <name>` 补发（H8）；token 缺失的模块不进索引（不调度、推送 401，日志明确告警）。

## 5. 铁律

1. **业务知识只进 worker.py + module.json**；公共能力只调 common；**禁止改 bridge 引擎**（引擎需求 → 配置化表达）
2. **调度时间以 module.json 为唯一事实源**，规范.md 不重复声明（防文档漂移）
3. **跨模块数据交换只走 common.shared_load/shared_save**（shared_load 支持 `max_age` TTL 校验），禁止互读文件
4. 缓存类共享数据必须带 TTL（防过期数据）
5. 失败必须 return 1（scheduler 才能感知补发）；测试必须用 `--dry-run`（真跑会推微信）
6. 新模块接入后跑 03 文档 A5 验证清单

## 6. 入站路由（交互式模块，B 定稿）

模块可声明 `inbound` 订阅，让模块**接收用户消息**（而不只是定时推送）：

```
用户消息 → 确认回复? → 【模块路由】命中?
    ├─ 命中 → spawn 模块（--inbound <text> --conversation <id>）
    │          rc=0 + stdout = 模块自答（bridge 回话）→ 消息被接管
    │          rc=3 = 模块主动转 agent
    │          rc 其他 = 记日志降级 agent（不阻塞用户）
    └─ 未命中 → agent 加工
```

- **多模块竞争**：按 `priority` 降序试，接管即止
- **安全边界**：确认回复永远最优先（PermissionGate 在最前，模块截不走确认流程）
- 交互逻辑用**模块落盘**（永久生效）优于 agent 会话记忆（5h 窗过期就忘）
- 应用示例：emotion 的"暂停/恢复关心"走 inbound（模块写状态文件），安慰话术走 agent 人设（A+B 混合）

## 6b. agents.md 编写规范（全索引化消费端，260827 定案）

**消费机制**：agents.md 全文**永不内联**进 agent 系统提示（AGENTS.md 已退役，部署态指引
经数据根 `instructions/` 装载）。模块启停后仅模块名 + module.json 的 `purpose` 一句话进入
迷你索引（`instructions/index-modules.md`）；agent 涉及模块任务时**按需读取** agents.md 全文。
因此：`purpose` 是 agent 对模块的第一印象与路由依据，必须一句话写准（如"待办管理与定时提醒"）。

**三条硬性写法**（工具循环轮次是免费模型延迟的大头，每多一轮 = 一次完整 LLM 往返）：

1. **路径常量**：数据文件路径约定必须直接写在 agents.md 里
   （如 `modules/modules_data/todo/tasks/YYYY-MM.json`），引导 agent 直达；
   **禁止**引导 agent「先读 module.json 推导路径」「先探索目录结构」——
   寻路轮次是纯浪费。
2. **步数上限**：常见操作（追加一条 / 查询列表）≤ 2 步完成（read + edit，或直接 write）；
   **禁止**「写后读回核对」类校验步骤——write/edit 的工具结果已回报成败。
3. **措辞禁令**：禁止「不要委派子代理探索」式强制串行表述；禁止含糊的
   「看着办」「自行判断目录」类措辞——每句指引都要让 agent 能照做直达。

**对照示例**：

```
✅ 好：「任务文件固定为 modules/modules_data/todo/tasks/YYYY-MM.json（按月分文件）。
        新增待办：读该文件（不存在则直接创建），在列表末尾追加一条后保存。」
❌ 坏：「先读取 module.json 了解数据约定 → 找到任务文件 → 写入 → 重新读取核对写入结果。」
```

## 6c. index 种子与硬索引（260827 议题1 定案）

**机制**：`<数据根>/instructions/index/<模块名>.json` 是检索位置表——条目 =
`关键词 → 内容文件位置`。bridge 硬索引（确定性代码）对入站消息做关键词子串匹配，
命中即在最后一步把指向文件的内容拼接进主链路提示词（路由不经模型，免费/小模型免疫）。
生命周期归 register：启用放置（无种子生成骨架，单条目指向 agents.md）、
关闭 `.off` 失效、卸载移除。

**模块作者义务**：模块目录随包一个 `index.json` 种子（预设关键词），格式：

```json
{
  "module": "todo",
  "entries": [
    {"kw": ["提醒", "待办", "#todo"], "file": "modules/todo/agents.md", "title": "todo 操作指引"}
  ]
}
```

- `kw`：非空字符串数组，可同义词多挂（写入时优先挂已有词，无则新建）
- `file`：相对数据根的路径；指向 agents.md（操作指引）或数据文件均可
- `title`：拼接时的材料块标题

**worker 可写约定**：worker 写记忆/更新条目时直接改写 `instructions/index/<本模块名>.json`
（写入顺序：先数据文件、后索引；indexer 命中后校验目标存在，死链自动跳过并告警）。

**记忆存储位置**（一句话约定，运作细节归记忆模块设计）：
跨模块/人格类记忆条目存 `modules/modules_data/memory/`，按条一文件；
只服务本模块调度的数据仍写本模块数据区。

## 7. 长任务分工（agent 型 → 自建 job 调度；代码型 → timer.json）

**agent 型长任务**（搜索/整合/写作类，如信息简报、总结报告、批量检索）：
- 走 **自建 job 调度（跨平台）**（`bridge.opencode_jobs`：cron 统一解析 → 三平台精确定时器
  ——Linux systemd OnCalendar / macOS launchd StartCalendarInterval / Windows schtasks
  （列表 cron 拆多任务）；到点触发纯 Python 执行器 `supervisor` 子命令：防重锁 → 执行
  `opencode run -- prompt`（job.env 注入 XDG，与 ACP 主链路同配置域）→ lastRun 状态写回 +
  jsonl 日志；统一入口 `<program> -m bridge.opencode_jobs supervisor <job.json>`，源码=
  venv python、打包=exe 自身；注意：此「opencode scheduler」为 wechat-claw 自带 supervisor
  体系，与 opencode 官方 scheduler 插件互不依赖，数据根独立（收敛形态在数据根
  opencode/config/scheduler））
- cron 表达边界：日字段与周字段同时非通配（cron OR 语义，平台定时器为 AND）→ **三平台
  一致拒绝登记**（报错提示，调整 cron 即可）；分钟步长不整除 60（`*/7`）schtasks 无法
  精确表达 → Windows 拒绝（Linux/macOS 正常）
- 模块携带 `job.template.json` → 部署者用 `bridge/opencode_jobs.py` 登记为正式 job（
  `install_job` 写 job.json + 生成平台定时器；`uninstall_job` 按 slug 前缀
  `<模块名>-` 精确清理）

**job.template.json 字段（通用引擎，无业务预设）**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `prompt` | **必填** | 任务指示语（模块作者必须写清楚"让 AI 干什么"；缺字段拒绝登记）。支持通用占位符：`{date}`、`{module_data}`（模块数据目录）、`{output_path}`（产物目录 = data_dir + `output_dir`）、`{settings:<键>}`（模块设置任意键，如 `{settings:briefing_topics}`）、`{custom_prompts}`（web 导入的自定义 prompt） |
| `name` / `title` / `slug` | 选 | 任务显示名 / 标题 / slug（默认取模块名） |
| `phase` | 选 | 对应 `schedule_from_settings` 的阶段（算 cron 用） |
| `offset_min` | 选 | 触发时刻提前分钟数 |
| `timeoutSeconds` | 选 | 超时（默认 1800） |
| `output_dir` | 选 | 产物子目录名（相对模块数据区，默认 `briefing`） |
| `workdir` | 选 | 执行工作目录（默认数据根） |

- 方向/参数化数据（如简报方向 keywords、字限、分类）**由模块自带文件承载**
  （如 `directions.json`），模板 prompt 里指引 AI 自行读取对应条目——引擎不代读任何
  模块业务文件（bridge 零业务知识）；`directions.json` 须为明文（管理后台读取其键
  作为 choice 候选，web 依赖）
- 任务指示也可用**模块自带模板** `prompts/base.prompt.md`（明文，无 `prompt` 字段时）：
  引擎原样读取（内容属模块，引擎不解读），其后自动追加用户自定义方向段
  （`prompts/custom/*.json`，web 导入的用户数据，模板内无法写占位符故由引擎代拼）。
  模板防篡改由模块完整性校验（sha256）兜底，无需加密。
  旧格式兼容：`prompts/base.prompt.enc`（作者加密）存在时引擎尝试解密；
  跨机密钥不同解密必然失败，按缺失处理（不再拒绝登记）。
- 触发时刻由 `schedule_from_settings`（module.json）按 settings 时刻 + `offset_min` 计算
- **模块与 opencode scheduler 零耦合**：job 是部署者的配置资产，模块装/卸不碰它（删除永远干净）
- scopeId 固定 `wechat-claw`，slug = `<模块名>-<任务名>`（定稿命名）
- 引擎 300s 超时保护不变——agent 型长任务不经过模块引擎

**代码型长任务**（备份/批量处理/抓数据类，纯代码）：
- 模块携带 `timer.json`（定时声明：schedule + 命令），register 安装时联动生成平台定时器
- 跑模块自己的长脚本（`<name>_timer_worker.py`），干重活 + 用模块 token 推送，一条龙不经过 scheduler

**典型链路**：模块声明 job.template.json → register 保存设置时自动渲染 + 登记（`bridge/jobs.py`）→
定时生成产物到模块数据区（如 `modules_data/<name>/briefing/`）→ 模块 worker 推送时消费。

## 8. common 边界清单（新增共享代码必须属于下列类别）

> 2026-08-19 修正：**vault 任务解析（task.py）已归模块**（Obsidian 模式私有解析器，随模块走，不进主体、不进 shared）。
> 共用走数据（shared）不靠代码 import——模块把值得共享的数据主动 `shared_save`，其他模块/agent 读 `shared_load`。

1. 防重/状态 IO 与共享数据（io.py + shared/；prune_state_file 在 bridge/state.py，io.py 薄包装）
2. 外部数据（weather.py 纯天气 + 气象预警；localdata.py 地方性区域服务，如花粉/台风）
3. 时间与历法（calendar.py 农历/节气/三伏、holidays.py 节假日）
4. 推送客户端（push.py）
5. 加解密（crypto.py）
6. 日志（log.py）
7. 位置常量（locations.py）
8. 用户数据面（location.py 位置 / habit.py 喜好：`.config/*.json` + prev 撤销，GUI 与模块统一经接口读写）

**shared 定位**：shared = 模块数据中"值得被其他模块使用"的部分，**必须模块作者主动 `shared_save` 才进入**；其余一律进 `modules/modules_data/<name>/`。shared 是共享视图（运行时派生），不是模块权威数据。

**阈值**：common 包单文件超 ~400 行，或出现"某功能只被一个模块用"→ 拆分子模块/回迁模块目录。

> **读全局配置**：基础设施配置层在 `bridge/config.py`（`from bridge.config import get`，点号路径如 `get("push.port")`）；
> 模块业务配置（vault 路径等）走模块 settings（settings.json），勿写进 config.yaml。

### common 可用接口速查（模块侧统一 `from common import X`）

> 单一事实源是 `modules/common/__init__.py` 导出面，本表为参考视图。

## 9. 模块更新（版本管理 + 每日自动更新 + 运行时完整性校验）

- **版本**：源 manifest 声明 `version`（semver）；安装/更新时写 `modules_data/<name>/installed.json`
  （{version, installed_at, source_id, **sha256, files**}——源模块附完整性基准，本地手写模块无基准）
- **更新判断**：每日定时（config `update.check_time`，默认 04:00）**指纹驱动**——源 manifest sha256 没变 = 源没动，零开销跳过；变了 → 逐模块（全局开关 && 模块 auto_update 开关 && 已安装）→ 更新
- **更新流程**（`bridge.module_source.update_module_from_source`，手动按钮共用）：拉新包 → 校验①清单 ②结构 ③**sha256**（不符拒收，保持旧版）→ **.bak 备份** → 复制（**跳过 token**，G1 不轮换）→ 复制失败恢复 .bak → 联动（schedule 重算 + job 重登记 + 豁免刷新）→ 记录新版本
- **数据区全程不碰**：settings.json（部署状态 + 业务设置）/countdown/briefing/custom prompts 均保留
- **静默**：更新成功/失败只写日志，不推送；web 模块列表显示版本与"自动更新关"标记，弹窗标题栏可关模块级自动更新
- **回滚**：不支持版本回滚（失败靠 .bak 恢复 + 哈希拒收；模块损坏可重装）

**运行时完整性校验（防部署机本地篡改）**：
- 调度前**快检**：scheduler 执行模块前按 installed.json 基准（sha256+files）重算比对——不符
  → 拒绝执行 + CRIT 告警；每日 04:00 更新后**全量**再扫一遍
- **系统改写自动刷基准**：register 联动改写 module.json（调度/设置保存）时自动重算基准并
  写回——系统合法变更不误报；**模块文件被外部修改（人肉/病毒/agent 绕过）才会被检出**
- **模块作者注意**：安装/更新后请勿手动修改模块文件（基准会立即失效）；token 不参与哈希
  （轮换不影响校验）

## 9b. 模块源发版（作者侧，发布流程）

- **manifest 重算**：改动模块文件后须重算该模块 sha256 并更新 `manifest.json` 的 `files`/`sha256`
  ——**`files` 清单必须覆盖 worker 的全部依赖**（含模块自带解析器，如 todo 的 `task.py`——
  漏列则安装缺文件、部署机调度即崩）
- **签名**：`python scripts/sign_manifest.py <模块库目录> <私钥hex>` → 产出 `manifest.sig`
  （部署机以内置公钥验签；manifest.json 与 sig 一起推送，改 manifest 必须重签）
- **换行**：仓库根 `.gitattributes` 为 `* -text`（Windows autocrlf 会改变签名字节导致验签失败）

## 10. 权限模型（豁免反转，默认最小化）

| 路径 | 默认 | 说明 |
|---|---|---|
| `modules/modules_data/<name>/**` | **无条件读写**（该模块） | 自己的数据区，无需声明 |
| `modules/<name>/**`（代码） | 只读 | agent 不改模块代码 |
| 本应用之外（~/文档 等） | 禁止 | 模块要动，须在 module.json 声明 `permissions`（越界申请） |

- **豁免声明 = 越界申请**：`"permissions": {"edit": ["<路径>"], "write": ["<路径>"]}`
- **设置路径自动豁免**：设置中 `type=path` 字段（如 Obsidian vault 目录）保存后**自动豁免**（`register --permissions` 汇总写 `.config/module-permissions.json`，合并进 opencode.jsonc 生效；卸载自动撤销）
- **安全交给用户**：装模块 = 信任它访问数据区；**不装来路不明的模块**（web UI 与 README 明示）
